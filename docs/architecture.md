# Architecture

The local browser talks to the Python preview server on loopback. The server reads an RTSP video stream, uses the most recent frame for YOLOX person detection and serves an annotated image. OpenCV CPU and experimental ONNX Runtime DirectML backends are supported. No video is recorded. Named camera profiles, including the RTSP URL and any embedded credentials, are stored unencrypted in browser local storage. Selecting a profile from the header starts its preview; the setup form is hidden until explicitly edited. Manual PTZ commands use VISCA-over-IP over UDP and are sent only after explicit user input to a configured private IPv4 address. The synthetic detection-to-motion controller remains separate from the live preview and does not issue camera commands.

Future work: persistent presenter selection, measured latency and frame age, manual-control disconnect handling, and automation design. Automatic physical motion must remain separate from the manual controls and be tested with a simulator and an operator before use.
